Heart rate

Use pywearable.heart_rate.get_heart_rate_statistics() as the canonical entry point. Named and fixed-resolution getters below specialize its feature or resolution while retaining the same trajectory contract.

This module contains all the functions related to the analysis of heart rate data.

pywearable.heart_rate.get_daily_heart_rate_statistics(loader, statistic=None, user_id='all', start_date=None, end_date=None, loader_kwargs={}, time_reference='auto', min_coverage=None)

Get heart rate statistics at a daily level.

This function computes the specified heart rate statistics over periods of one day. time_reference="auto" uses local calendar days. Statistics are reported for each day from start_date to end_date (excluded) and for the users specified by user_id. The function used to load heart rate data is the load_heart_rate(). If loader-specific arguments are required, it is possible to set them using the loader_kwargs argument. The function returns a pandas.DataFrame indexed by user_id and local_time.

Parameters:

  • loader (pywearable.loader.base.BaseLoader) – An instance of a data loader.

  • statistic (str) – The list of heart rate statistics to be computed.

  • user_id (str or list, optional) – The id(s) for which minHR must be retrieved, by default “all”

  • start_date (datetime.datetime or datetime.date or str or None, optional) – Start date for data retrieval, by default None.

  • end_date (datetime.datetime or datetime.date or str or None, optional) – End date for data retrieval, by default None

  • loader_kwargs (dict) – Keyword arguemnts for the load_heart_rate loading function of the loader, by default no keyword arguments are passed.

  • time_reference (str)

Returns:

Daily-level heart rate statistics.

Return type:

pandas.DataFrame

pywearable.heart_rate.get_heart_rate_statistics(loader, statistic=None, user_id='all', start_date=None, end_date=None, resolution='day', loader_kwargs={}, time_reference='auto', aggregation=None, min_coverage=None, cycle_kwargs=None, min_valid_children=None)

Return heart-rate features at one resolution or along a hierarchy.

A scalar resolution preserves the ordinary heart-rate extraction API. A resolution sequence defines increasingly larger windows: features are first calculated from samples at the first resolution, then each upper level aggregates the preceding rows with equal child weighting.

Parameters:

  • loader (BaseLoader) – Loader providing heart-rate samples and, for cycles, sleep sessions.

  • statistic (str, sequence of str, or None) – Primary heart-rate features. None requests every registered feature; resting heart rate is available for daily or cycle windows.

  • user_id (str or list, default "all") – Participant identifiers.

  • start_date (timestamp-like or None) – For fixed and calendar windows, the exact half-open analysis interval [start_date, end_date). For cycle resolutions, the bounds select cycle calendar labels and selected cycles are never clipped. Without bounds, each participant uses only their observed trajectory.

  • end_date (timestamp-like or None) – For fixed and calendar windows, the exact half-open analysis interval [start_date, end_date). For cycle resolutions, the bounds select cycle calendar labels and selected cycles are never clipped. Without bounds, each participant uses only their observed trajectory.

  • resolution (str, timedelta, or sequence, default "day") – One window resolution or a strictly increasing hierarchy, such as ["1h", "cycle_night", "monthly"].

  • loader_kwargs (dict) – Extra keyword arguments passed to loader.load_heart_rate.

  • time_reference ({"auto", "local", "utc"}, default "auto") – Clock used for fixed windows. auto selects UTC for purely subdaily extraction and local time when calendar or cycle parents require it. Explicit UTC is invalid when any sleep-defined cycle is requested.

  • aggregation (str, sequence, nested sequence, or None) – Operations for levels above the primary one. None uses the standard numeric operations. With more than one upper level, provide one nested specification per level, for example [["mean"], ["mean", "p90"]].

  • min_coverage (float, sequence of float or None) – Minimum coverage required at each requested resolution. The first value controls raw samples to the primary feature window; later values control valid child windows to each parent. A scalar applies to every level, while a sequence supplies one value per resolution. An individual None disables filtering at that level. If primary cadence cannot be inferred, its coverage is unknown: the feature is retained when no primary threshold is requested and excluded when one is requested.

  • cycle_kwargs (dict or None) – Options forwarded to pywearable.cycle.get_intervals(), such as missing_end="midnight".

  • min_valid_children (int, sequence of int or None) – Minimum valid child windows required at each upper resolution. A scalar applies to every upper level. A sequence supplies one value per resolution and must use None for the primary level. When both count and coverage thresholds are set, both must pass.

Returns:

A (user_id, time) trajectory containing each requested feature and its __coverage column. Hierarchical output names retain the full calculation path and include immediate child coverage columns. Fixed-duration output also contains the alternate clock and the timezone UTC offset for each window.

Return type:

pandas.DataFrame

Examples

Calculate ordinary five-minute features:

get_heart_rate_statistics(loader, resolution="5min")

Average hourly mean heart rate within each main-sleep cycle, then return its monthly mean and 90th percentile:

get_heart_rate_statistics(
    loader,
    statistic="heart_rate_mean",
    resolution=["1h", "cycle_night", "monthly"],
    aggregation=[["mean"], ["mean", "p90"]],
    min_coverage=[0.5, 0.7, 0.8],
    min_valid_children=[None, 3, 2],
)
